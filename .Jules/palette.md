## 2024-07-15 - Accessible Custom Tab Toggles
**Learning:** When building custom interactive components like tab toggles from `div` elements, they are invisible to screen readers and difficult to navigate for keyboard users, breaking accessibility. Using native semantic elements (like `<button type="button">`) is best, but they still require manual ARIA wiring (`role="tablist"`, `role="tab"`, `role="tabpanel"`, `aria-selected`, `aria-controls`) and custom JavaScript for "roving tabindex" (listening for arrow keys to shift focus) to fully emulate native tab behavior. Additionally, default button styling needs to be stripped, while explicitly maintaining `:focus-visible` styles to ensure keyboard users can still see their focus state without bothering mouse users.
**Action:** Always convert custom `div` interactive toggles to semantic elements (`<button>`) and pair them with the appropriate ARIA roles, states, keyboard event listeners (handling `e.preventDefault()` to stop scrolling), and explicit `:focus-visible` CSS rules when replacing default styles.
