## 2023-10-27 - Custom Tab Toggles Must Manage TabIndex for Accessibility
**Learning:** When implementing custom tab toggles (like a login/signup switch) using native `<button>` elements with `role="tab"`, merely adding `aria-selected` is insufficient for proper keyboard navigation. If all tabs remain in the tab order (`tabindex="0"`), keyboard users have to tab through unselected tabs to reach the active form content.
**Action:** Always implement a roving tabindex or ensure inactive tabs have `tabindex="-1"` while the active tab has `tabindex="0"`. This allows screen reader and keyboard users to tab once to enter the tablist, arrow between tabs (requires extra JS for arrows, but basic tab logic applies), and tab again to immediately enter the `role="tabpanel"` form associated with the active tab. Also, always add `:focus-visible` to strip-styled native buttons so keyboard navigation remains visually clear.
