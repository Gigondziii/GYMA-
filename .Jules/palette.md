## 2024-05-24 - Accessibility improvements for toggle elements
**Learning:** In GYMA, form toggles (like Login vs Signup) were built with `<div>` elements possessing `onclick` attributes but no native keyboard interactivity or semantic structure. Using ARIA roles like `tablist`, `tab`, and `tabpanel` natively improves screen reader experience, but custom controls also need a standard "roving tabindex" pattern and explicit arrow-key support. Furthermore, custom buttons need `:focus-visible` outlines defined explicitly (using GYMA's `#00ff41` brand color) to ensure visual accessibility for keyboard navigation without breaking mouse interactions.
**Action:** When implementing custom toggle/tab interfaces in GYMA, convert clickable `<div>` elements to semantic `<button type="button">`, implement roving tabindex (`0` for active, `-1` for inactive) supported by arrow-key navigation (using `keydown` and `e.preventDefault()`), explicitly define `:focus-visible` state utilizing `#00ff41`, and strip default button styling. Apply ARIA `tablist`/`tab`/`tabpanel` attributes as required.
