## 2024-07-23 - Accessible Custom Tab Toggles
**Learning:** When stripping default browser styling from native elements (like `<button>`) to create custom UI components like tab toggles, the native `:focus` ring is often inadvertently removed. This severely harms keyboard accessibility as users can no longer see which element is active. Additionally, using standard `<div>` elements with `onclick` events instead of native buttons breaks expected semantic behavior for screen readers and keyboard navigation.
**Action:** When implementing custom interactive components such as form toggles, ensure native `<button type="button">` elements are used. Always explicitly define a visible `:focus-visible` CSS state to restore clear keyboard navigation visibility while avoiding unnecessary outlines for mouse users. Utilize ARIA roles (`role="tablist"`, `role="tab"`, `role="tabpanel"`) and sync `aria-selected` properties alongside a roving `tabindex` pattern supported by `keydown` arrow navigation to guarantee full accessibility.
