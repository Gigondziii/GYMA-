## 2024-12-06 - Synchronize .focus() with custom roving tabindex logic
**Learning:** When building custom tab interfaces with a roving tabindex pattern, relying solely on setting `tabindex="0"` for the active tab and `-1` for others isn't enough to handle mouse clicks reliably. If a user clicks a tab, the visual state changes, but the keyboard focus might not update or sync with `document.activeElement` correctly across all browsers or contexts.
**Action:** When creating custom tab toggles or UI interaction buttons, explicitly call `.focus()` on the newly activated tab button upon state changes (like mouse clicks or programmatic switches) to ensure keyboard focus synchronizes with the visual state and the DOM's `activeElement`. This prevents disruption of the roving tabindex strategy during arrow-key navigation.
