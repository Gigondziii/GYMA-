
## 2025-03-09 - Upgrading custom div tabs to native accessible button tabs
**Learning:** When replacing custom `<div>` based tab toggles with semantic native `<button type="button">` elements to improve accessibility, the default browser styling (background, border, font-family, outline) must be explicitly stripped from the existing CSS class (e.g. using `background: none; border: none; font-family: inherit; outline: none;`) to prevent breaking the visual design. Furthermore, implementing a roving tabindex requires setting `tabindex="0"` for the active tab and `tabindex="-1"` for inactive tabs, and adding keyboard event listeners on the `tablist` container. Modulo arithmetic (e.g., `(currentIndex + 1) % tabs.length`) provides an elegant solution for cyclic left/right arrow key navigation without complex conditionals. Finally, manually calling `.focus()` on the newly active element ensures the visual focus state synchronizes correctly with keyboard navigation.
**Action:** When working on custom UI components, always verify if native semantic HTML elements can be used instead of `div`s. If upgrading elements to buttons, ensure default styles are stripped out, and implement complete keyboard navigation support (roving tabindex and arrow keys) matching the component's ARIA pattern (e.g., tablist/tab/tabpanel). Ensure `focus-visible` styles are provided for clear visual feedback.
