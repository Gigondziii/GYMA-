## 2025-08-01 - Interactive Element Keyboard Accessibility
**Learning:** When replacing generic elements like `div` with native interactive elements like `button` for custom UI components such as tab toggles, default browser focus outlines must be explicitly overridden (e.g., via `:focus-visible`) to maintain the application's visual design while ensuring clear keyboard navigation visibility. Also, custom tab components require implementing roving tabindex and arrow-key navigation to fully support screen readers and keyboard users.
**Action:** Always use native semantic elements (like `<button type="button">`) for interactive UI components, strip their default styling while preserving custom `:focus-visible` outlines aligned with the theme color, and implement standard ARIA tablist/tab patterns including roving tabindex for keyboard support.
