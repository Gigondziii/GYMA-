## 2024-10-27 - [Native Button Tabs & Keyboard Navigation]
**Learning:** When building custom tab toggles (like a login/signup switcher), using styled `<div>` elements breaks accessibility. Screen readers won't announce them correctly, and keyboard users can't interact with them. Even if `onclick` is present, it's missing the required `tabindex`, `role="tablist"`, `role="tab"`, and keydown event handling needed for a proper tab paradigm.
**Action:** Always replace interactive `<div>` elements with native `<button type="button">` elements. Strip default styles (`background: none; border: none; font-family: inherit;`) to maintain visual design, add `:focus-visible` styles for clear keyboard outlines, apply ARIA tab roles (`tablist`, `tab`, `tabpanel`), manage states (`aria-selected`), and implement roving `tabindex` with arrow key support to prevent page scrolling while navigating tabs.
