## 2024-05-30 - Accessible Form Toggles with Roving Tabindex
**Learning:** In the standalone frontend app, interactive tab toggles (like Log In / Sign Up in `login.html`) were implemented as `<div>` elements with `onclick` handlers, breaking keyboard accessibility and screen reader support. Proper semantics require `<button>` elements with `role="tab"`, `role="tablist"` containers, and a roving tabindex for arrow key navigation to align with W3C patterns.
**Action:** Always convert custom interactive components to use native semantic elements (e.g., `<button type="button">`) with appropriate ARIA roles, and implement dynamic tabindex management combined with keyboard event listeners to support standard UI interaction patterns (like Left/Right arrows for tabs). Ensure `:focus-visible` styles are set to indicate active focus clearly without mouse outline side-effects.
