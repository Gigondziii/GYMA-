## 2024-05-19 - Inaccessible Custom Tab Pattern
**Learning:** Found custom tab/toggle components constructed from clickable `<div>` elements rather than native `<button>` tags. This pattern strips semantic meaning (`role`), structural relationships (`aria-controls`, `aria-labelledby`), and inherent keyboard functionality, completely excluding screen reader and keyboard-only users from interacting with the authentication flows.
**Action:** Always refactor `<div>`-based tabs into `<button type="button">` with `role="tab"`. Ensure the container has `role="tablist"` and contents use `role="tabpanel"`. Maintain visual consistency by stripping default browser button CSS and replacing it with strong `:focus-visible` outlines. Crucially, bind JavaScript logic to manage both `aria-selected` and roving `tabindex`, accompanied by arrow-key navigation handlers.
