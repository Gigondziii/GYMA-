## 2024-07-19 - [Custom Interactive Element Semantics and Keyboard Support]
**Learning:** When creating custom tab components or toggles (like the login/signup form switch), replacing plain div elements with semantic `<button type="button">` combined with proper ARIA roles (`role="tablist"`, `role="tab"`, `role="tabpanel"`, `aria-selected`, `aria-controls`) is crucial. Moreover, proper keyboard support requires implementing a roving `tabindex` (`0` for active, `-1` for inactive) along with JavaScript to handle Arrow key navigation, allowing users to traverse options seamlessly without trapping their focus. Explicitly defining a `:focus-visible` state rather than just `:focus` helps ensure keyboard navigators get visual feedback (like the theme's #00ff41 outline) without unnecessarily distracting mouse users.
**Action:** Always apply native interactive elements over `div`s with `onclick` where possible. Check that `tabindex` and ARIA attributes dynamically update to reflect the state of custom tab sets. Always test `ArrowLeft`/`ArrowRight` key support and explicit `:focus-visible` styles using programmatic keyboard interactions in Playwright.
