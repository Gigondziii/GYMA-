## 2024-05-18 - [Custom Tab Toggle Keyboard Nav]
**Learning:** Custom tab toggles using div elements and CSS translate sliders are inaccessible to keyboard users and screen readers out of the box because they lack semantic meaning and focusability. Simply adding a click handler to a div is not enough.
**Action:** When implementing custom tab UI components, always use native `<button type="button">` elements to get built-in focus and activation behavior. Remove their default styling with `background: none; border: none; font-family: inherit; outline: none;` and add explicit `:focus-visible` styling (like the apps `#00ff41` accent color) for clear keyboard indicators without bothering mouse users. Add proper ARIA roles (`role="tablist"`, `role="tab"`, `role="tabpanel"`) and properties (`aria-selected`, `aria-controls`, `aria-labelledby`). Crucially, implement a roving `tabindex` (setting the active tab to `0` and inactive to `-1`) combined with a `keydown` listener for `ArrowRight`/`ArrowLeft` keys to allow smooth keyboard navigation between tabs.
