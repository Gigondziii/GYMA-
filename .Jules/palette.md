## 2024-06-12 - Semantic Buttons and ARIA in Custom Tabs
**Learning:** Found a critical accessibility gap where custom tab implementations (like the login/signup toggle) used generic `<div>` tags instead of native interactive elements (`<button type="button">`). Without native buttons and full ARIA attributes (`role="tablist"`, `role="tab"`, `aria-selected`, `aria-controls`), the interaction completely broke screen readers and keyboard navigation (missing natural focus, Tab sequence). Relying on default mouse-click paradigms hides severe a11y issues.
**Action:** When creating custom tab components, always build with native semantic interactive elements (`<button>`), supply ARIA tab patterns, strictly strip default styles if necessary, and use `:focus-visible` with high contrast for predictable keyboard-driven feedback.
