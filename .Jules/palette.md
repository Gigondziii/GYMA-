## 2024-05-18 - Accessible Custom Tab Toggles
**Learning:** When building custom toggle switches for forms (like Log In vs Sign Up), using `<div>` elements with `onclick` breaks keyboard navigation and screen reader support. Native `<button>` elements should be used, but they require stripping default browser styling (`background: none; border: none; font-family: inherit; outline: none;`) to maintain the visual design.
**Action:** Always replace `<div>` based custom buttons with native `<button type="button">`. Add appropriate ARIA roles (`role="tablist"`, `role="tab"`, `role="tabpanel"`, `aria-selected`, `aria-controls`), apply explicit `:focus-visible` states, and implement roving `tabindex` with arrow-key navigation (using `e.preventDefault()` to stop scrolling) to ensure a fully accessible, robust component.
