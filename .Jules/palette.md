## 2024-07-03 - Native Buttons and ARIA Attributes for Custom Tabs
**Learning:** Custom UI tabs constructed with generic `<div>` tags and `onclick` handlers are completely invisible to screen readers and keyboard users (no tab focus, no role context, no active state announcements). Specifically, programmatic focus shifts or non-native outlines can be inconsistent; native `<button>` tags provide out-of-the-box keyboard support.
**Action:** When implementing custom tab UI patterns, always use `<button type="button">`, strip default browser styling if needed, explicitly define `:focus-visible` styles for clear keyboard navigation, and assign proper ARIA roles (`role="tablist"`, `role="tab"`, `role="tabpanel"`) and state attributes (`aria-selected`, `aria-controls`) to ensure full accessibility parity with visual design.
