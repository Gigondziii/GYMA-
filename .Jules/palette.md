## 2024-11-20 - Accessible Custom Tab UI Toggles
**Learning:** Building accessible custom tab toggles (like form switchers) requires converting visual `<div>` buttons to semantic `<button type="button">` elements. Merely adding `onclick` isn't enough for keyboard users. Adding proper ARIA tab roles (`tablist`, `tab`, `tabpanel`) combined with a roving tabindex pattern and arrow key navigation ensures the widget is fully navigable for assistive technologies.
**Action:** Always convert generic elements acting as tab toggles to native `<button>` elements, strip default styling (using `background: none; border: none; font-family: inherit; outline: none;`), define explicit `:focus-visible` styling (with the brand color), and implement full roving tabindex keyboard navigation.
