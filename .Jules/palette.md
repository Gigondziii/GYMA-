## 2024-06-11 - Converting custom tabbed toggles to native accessible patterns
**Learning:** In GYMA's UI, interactive custom tab controls (like `.form-toggle`) were historically built with non-semantic `<div>` tags using `onclick` handlers, rendering them inaccessible via keyboard. This pattern is common but completely breaks keyboard navigation for screen reader users and power users. While `<div>` elements can be given a tabindex, a much more robust approach is to swap them for native `<button>` tags with default browser styling stripped away.
**Action:** When creating or refactoring custom UI toggle groups, always use `<button type="button">` combined with proper ARIA attributes (`role="tablist"`, `role="tab"`, `aria-selected`, `aria-controls`, `role="tabpanel"`) to ensure the component behaves reliably for all assistive technologies. Furthermore, when stripping default styles, remember to explicitly redefine the `:focus-visible` state using `outline` to maintain clear visual feedback for keyboard users without adding visual noise for mouse interactions.
