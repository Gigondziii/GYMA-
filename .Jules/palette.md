## 2024-07-11 - Custom Tablist Accessibility (Log In Toggle)
**Learning:** Custom UI toggles acting like tabs (such as the "Log In" / "Sign Up" toggle) are frequently built with basic `<div>` tags and `onclick` handlers, breaking keyboard navigation and screen reader semantics. Upgrading them with native `<button role="tab">` inside a `role="tablist"` alongside roving `tabindex` (using ArrowRight/ArrowLeft navigation) dramatically improves keyboard accessibility while preserving the original design. Applying `:focus-visible` ensures clear focus rings only appear when navigating via keyboard.
**Action:** When implementing custom tab toggles or UI interaction buttons, use native `<button>` elements explicitly defined with `type="button"`. Add appropriate ARIA roles (`role="tablist"`, `role="tab"`, `aria-selected`, `aria-controls`) and `role="tabpanel"` with `aria-labelledby` to their corresponding content containers. Strip default browser styling, implement `:focus-visible`, and use a roving tabindex supported by arrow-key navigation.
