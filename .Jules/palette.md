## 2024-05-24 - Accessible Tabs & Roving Tabindex Synchronization
**Learning:** Converting custom `<div>`-based tab widgets into fully accessible components requires more than just `<button>` elements and ARIA roles. It requires a roving `tabindex` strategy where keyboard navigation (Arrow keys) explicitly calls `.focus()` on the newly selected element. Without this explicit focus synchronization, the browser's programmatic focus becomes detached from the ARIA state, breaking `:focus-visible` styling and rendering the component confusing for screen readers and keyboard users.
**Action:** When implementing custom tablists, always pair ARIA roles (`tablist`, `tab`, `tabpanel`) with native `<button>` elements, strip default browser styling, apply a roving `tabindex` (0 for active, -1 for inactive), and use `document.activeElement` coupled with explicit `.focus()` calls during Arrow key navigation to ensure visual and programmatic state remain perfectly synchronized.
