## 2024-05-16 - Semantic Buttons for Interactive Tab Toggles
**Learning:** Custom tab toggles implemented using `<div>` elements with `onclick` handlers are invisible to keyboard navigation and screen readers. When users rely on a keyboard to navigate, they cannot focus on or interact with the tabs. Even with styling, without the proper ARIA roles (`role="tablist"`, `role="tab"`, etc.), screen readers cannot announce the function and state of the toggle correctly.
**Action:** Always use native `<button>` tags for interactive controls like tab toggles, explicitly stripping browser defaults with CSS (`background: transparent`, `border: none`, etc.) if needed. Pair this with a clear `:focus-visible` outline for visual keyboard accessibility, and standard ARIA tab attributes (`role="tab"`, `aria-selected`, `aria-controls`) for screen readers.
