## 2024-05-24 - Semantic Buttons for Custom Tab Interfaces
**Learning:** When custom tabbed interfaces (like the login/signup form toggles) are implemented using simple `<div>` elements with `onclick` handlers, they fail completely for keyboard-only users who rely on the `Tab` key and screen readers. They do not implicitly receive focus, nor do they trigger semantic meaning about the interaction.
**Action:** When implementing custom tab UI components, always replace `<div>` with semantic `<button type="button">` elements to preserve accessibility. Ensure ARIA roles (`role="tablist"`, `role="tab"`) and properties (`aria-selected`, `aria-controls`) are added. Support roving `tabindex` mapping and manual arrow-key navigation handlers, while preserving visual styles by stripping default browser styling (e.g. `background: none`, `border: none`) and explicitly adding `:focus-visible` styling indicating focus without impacting mouse users.
