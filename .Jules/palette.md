## 2024-05-15 - Interactive Tab Toggles Accessibility
**Learning:** Custom UI components acting as tab toggles are often implemented with un-semantic `<div>` tags and inline `onclick` handlers, causing them to fail basic accessibility tests. To make them fully accessible, they require native `<button>` tags (with stripped default styles), explicit ARIA roles (`role="tablist"`, `role="tab"`, `role="tabpanel"`), clear focus states (via `:focus-visible`), and a Javascript-managed roving tabindex (`tabindex="0"` on the active tab and `tabindex="-1"` on inactive tabs) with Arrow Key support.
**Action:** When implementing or fixing custom UI toggle components, default to replacing non-interactive elements with semantic `<button type="button">` tags. Apply the complete ARIA tablist pattern, and include a Javascript event listener for Arrow-key navigation (using `e.preventDefault()` to stop unwanted scrolling).
