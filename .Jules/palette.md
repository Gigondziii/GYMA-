## 2023-10-29 - Accessible Tab Navigation
**Learning:** Custom UI tabs implemented as standard `<div>` elements are entirely invisible to screen readers and cannot be focused with the keyboard. Simply replacing them with `<button>` elements is insufficient; they require ARIA roles (`tablist`, `tab`, `tabpanel`), associated relationships (`aria-controls`, `aria-labelledby`), and dynamic state tracking (`aria-selected`).
**Action:** When implementing custom tab UI elements in the future, always use native `<button>` elements, add the necessary ARIA role structure, and ensure state changes update `aria-selected`. Implement a roving tabindex (`tabindex="0"` for active, `-1` for inactive) along with an event listener that handles `ArrowLeft`/`ArrowRight` keypresses for smooth, intuitive keyboard navigation. Ensure the newly active tab explicitly receives focus so the visual state syncs correctly.
